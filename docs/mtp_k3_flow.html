RWKV7MTPModule.forward(h, tok_emb) — the same module and weights are applied at every depth k = 0, 1, 2. Nothing here knows about depths; recursion lives in how it is called.
~94M trainable: ln_h + ln_tok + proj + one RWKV-7 block (C=2560) backbone (2.9B), emb, W_out all frozen at inference one WKV state per depth k is kept (stateless MLP head this is not)
RWKVWithMTP.forward_loss(idx, targets) — every position i of the (B,T) chunk is computed in parallel; depth-k inputs are ground-truth tokens (teacher forcing), never the head's own output. This parallel form reproduces exactly the recursive computation used at inference.

The teacher for depth k at row i is the frozen backbone's own distribution at position i+k+1 (the position whose next token is exactly x[i+k+2], the depth-k target) — restricted to its top-64 tokens, renormalised (--distill-topk 64 --distill-lambda 0.5). Because embeddings and W_out are frozen, gradients exist only for ln_h/ln_tok/proj/block — your 94M. Causality: depth-k's injected token at row i is x[i+k+1], and its state summarizes rows j ≤ i — nothing from beyond the target is ever consumed.
One draft/verify round at stream end p (RWKV7HeadRunner.draft_chain + the generate loop in spec_decode.py). Why the catch-up cells (steps 5 & 8) exist: depth k's input x_k[j] needs the token at stream position j+k+1, so depth k always lags the stream end by k ingestions. Each round, the newly committed token cₚ₊₁ unblocks exactly one pending input per depth (j = p−k) — the runner does this bookkeeping anyway via advance(); the draft chain simply does it early, plus the one tentative ingestion at j=p that produces the next draft.

Measured with this exact scheme (FastMTP, self-distilled shared head): conditional acceptance ≈ 80% (d₁) · 56% (d₂) · 36% (d₃) — versus vanilla head-reuse 70 / 11 / 2%. The recurrent state carried across depths is precisely where the extra depth-2/3 acceptance comes from.
